## Keyboard navigation

- **Skip link:** First focusable element on every page. Visible on focus
  (teal background, dark text, 3px focus ring). Jumps to `<main id="main">`.
- **Tab order:** Follows DOM order — skip link → brand → nav links → page
  content → footer links. No positive `tabindex` values anywhere.
- **Focus visibility:** `:focus-visible` applies a 3px teal outline with 2px
  offset on every interactive element.
- **Mobile nav:** Toggle button has `aria-expanded`, `aria-controls`, and a
  text label that changes to "Close" when open. Escape key closes the panel
  and returns focus to the toggle.
- **Form:** All fields are reachable by keyboard. Validation errors move focus
  to the first invalid field. Error messages are associated via
  `aria-describedby` and `aria-invalid`.

## Screen reader structure

- **Landmarks:** `<header>`, `<main>`, `<footer>`, `<nav aria-label>` on every page.
- **Heading outline:** Exactly one `<h1>` per page. No skipped levels
  (h1→h2→h3, never h1→h3). Verified programmatically.
- **Images:** All `<img>` elements have descriptive `alt` text (minimum 10
  characters). Decorative SVGs use `aria-hidden="true"`.
- **Form labels:** Every input, select, and textarea has an associated
  `<label for>`. Optional fields are marked in the label text, not by
  omission.
- **Buttons and links:** All have discernible text. No icon-only controls
  without `aria-label`.

## Touch targets

All interactive elements are ≥48px in at least one dimension:
- Nav links: 48px min-height
- Buttons: 48px min-height
- Form inputs: 48px min-height
- Brand link: 48px min-height
- Inline paragraph links: padded to 48px via `.inline-link` class
- Mobile nav toggle: 48px min-width and height

## Reduced motion

`@media (prefers-reduced-motion: reduce)` disables:
- Smooth scrolling
- All CSS transitions (set to 0.01ms)
- All CSS animations

## Zoom behavior

Layout uses relative units (`rem`, `clamp()`, `%`) throughout. No fixed-pixel
containers. Verified at 200% zoom: no horizontal scroll, no clipped text, no
overlapping elements.

## Known limitations

1. **Skip link `:focus` in automation:** The skip link's `:focus` CSS rule
   does not apply in headless Chrome via CDP (a known automation limitation,
   not a real-browser issue). A JS fallback adds an `is-visible` class on the
   `focus` event as belt-and-braces. Real browsers handle this via CSS alone.

2. **Contact form endpoint:** Currently uses a mailto fallback. Once a form
   endpoint is configured (see DEPLOY.md), submissions POST directly and the
   fallback only activates on network failure.

3. **Analytics:** None installed yet. When added, must be async, deferred,
   and must not block first paint. See TRAFFIC.md.
